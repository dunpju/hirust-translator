## 1. 设计原则

1. **单手可达**：核心操作（开始/停止、口音切换）全部压在拇指热区（屏幕下 1/3）；
2. **复用桌面信息架构**：同样的三段式（状态 / 记录 / 控制）与 S0–S5 状态机，仅布局适配竖屏；
3. **Material 3 暗色**：色值与桌面版对齐，品牌观感一致；
4. **语音优先**：全程无必须的文字输入，规避移动端 IME 打断。

## 4. 关键交互时序

### 4.1 录音权限 + 启动

```
 用户          MainActivity          系统           Rust 引擎
  │ 点击开始录音    │                  │                │
  │──────────────▶│ 无 RECORD_AUDIO   │                │
  │               │──requestPermission▶                │
  │◀──────── 系统授权弹窗 ─────────────│                │
  │──允许────────▶│                  │                │
  │               │ AudioRecord(16k PCM_FLOAT) 线程启动 │
  │               │──setPaused(false)─────────────────▶│
  │               │──feed_pcm(100ms 块) ══════════════▶│ 连续推流
  │ 说话…          │                  │  VAD→识别→翻译  │
```

拒绝权限：主按钮保持可点，点击再次拉起授权（`shouldShowRequestPermissionRationale` 时给文字引导）。

### 4.2 译文播报（回声防护联动）

```
 Rust 引擎                    Kotlin
  │ on_utterance(ts,zh,en) ───▶ 卡片上屏
  │ Edge-TTS 合成 mp3           │
  │ on_mp3(bytes) ────────────▶ 写临时文件→MediaPlayer 串行队列
  │  (TTS 队列阻塞等待)          │      播放中…扬声器出声
  │◀──────────── playbackDone()─│ 播放完成
  │  解锁队列 → 下一句           │
  │  回声防护期间 VAD 丢弃输入    │  （AudioRecord 仍在推流，Rust 侧静默）
```

关键约定：**每收到一段 `on_mp3` 播完必须回调 `playbackDone()`**（含播放失败分支），否则 Rust TTS 队列会挂起（180s 兜底超时）。

## 6. 与桌面版差异对照

| 维度 | 桌面（egui） | 安卓（Compose） |
|---|---|---|
| 音频采集 | Rust cpal（WASAPI） | Kotlin AudioRecord → `feed_pcm` 推流 |
| 音频播放 | Rust rodio | Kotlin MediaPlayer ← `on_mp3` 回调 |
| 回声防护 | Rust 内部闭环（tts_playing 门） | 跨语言：`on_mp3` ↔ `playbackDone()` |
| 暂停语义 | 暂停不卸载引擎，秒级恢复 | 同（`setPaused` + 停推流） |
| 设置 | 侧滑面板（音色热更新） | ⏳ 后续版本（配置经 `cfg_toml` 传入引擎） |
| 模型下载 | 首次运行弹窗 | 首次运行内嵌卡片 |
| 快捷键 | Space/1/2/M/E/R/Ctrl+, | 无（纯触控） |
| 历史重播 | 卡片 [重播] 按钮 | ⏳ 长按菜单 |

## 7. 后续迭代（M6 候选）

1. **设置页**：音色试听、LLM Key、断句灵敏度（写回 cfg 后重建引擎）；
2. **输入电平条**：`AudioRecord` 缓冲 RMS 直算，零跨语言开销；
3. **前台服务**：通知栏"同传中"常驻 + 息屏采集；
4. **会话卡片长按菜单**：复制 / 重播 / 删除；
5. **横屏/平板**：记录区双栏；
6. **Release 签名**：CI 注入 keystore 出正式包（当前 debug 签名）。
